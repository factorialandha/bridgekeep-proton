# Testing with your own account (Windows)

CI can't log in to Proton, so it stops at "Bridge starts and its forwarders
are reachable". This walkthrough covers the rest with a real account, on
Windows with Docker Desktop. Go through it before you promote anything to
`main` or publish an image.

It takes about 30 minutes, plus however long the first sync takes. Nothing
here changes your mailbox, except the optional SMTP step, which sends one
mail to yourself.

## 0. Set up

Run steps 1 to 7 in **WSL (Ubuntu)**, not Git Bash. The login and the live
check need an interactive terminal, and Git Bash's terminal often fails with
`the input device is not a TTY`.

1. In Docker Desktop, open **Settings > Resources > WSL integration** and turn
   it on for your Ubuntu distro.
2. In Ubuntu:

   ```sh
   sudo apt-get update && sudo apt-get install -y make git
   cd /mnt/c/projects/bridgekeep-proton
   git fetch origin && git checkout preview && git pull
   make preflight          # preflight: ok (Docker Desktop, compose 2.x)
   ```

   `make preflight` checks Docker, Compose and BuildKit. If WSL has its own
   Docker engine (Ubuntu's `docker.io`) instead of Docker Desktop's, it
   prints a note and carries on. That's fine for testing, as long as you run
   every step from this WSL shell, step 8 included. Git Bash talks to Docker
   Desktop, which has a separate image and login volume.

3. Check that the repo is clean and on the pinned version:

   ```sh
   git status --short      # nothing listed
   cat bridge-version.env  # BRIDGE_VERSION=3.27.2
   ```

Have your Proton password and your 2FA app ready. Use an authenticator app
(TOTP) for 2FA. A hardware security key can't be reached from inside the
container.

## 1. Build and smoke test

```sh
make build
make test
```

`make build` compiles Bridge from the pinned source, which is the same build
your Linux host will use. It fails if the source doesn't match the pinned
hash. The first build takes 5 to 15 minutes. Later ones are faster. `make test` should end with
`smoke test passed`.

## 2. Log in (one time)

```sh
make init
```

At the `>>>` prompt:

1. `login`: enter your Proton username and password, then the 6-digit 2FA
   code. If your account uses a separate mailbox password, it asks for that
   next.
2. `info`: note the IMAP/SMTP **username** and **password**. This password
   is generated by Bridge. It is not your Proton password. Keep it in your
   password manager. Don't paste it into a file in the repo.
3. `help`: if it lists an automatic-updates setting, turn it off.
4. `exit`

The init container uses log driver `none` and is removed when you exit, so
the password from `info` isn't kept anywhere by Docker. To check:

```sh
docker ps -a --filter name=bridge-init   # nothing listed
```

## 3. Start it and wait for healthy

```sh
docker compose up -d
docker compose ps        # repeat until STATUS shows (healthy), up to ~2 minutes
docker compose logs --tail 50 bridge
```

Healthy means Bridge is running and answering on IMAP and SMTP. It does not
prove the login works; step 5 checks that. If it stays `starting` or turns `unhealthy`, see step 8.

Check that nothing is published on the Windows host:

```sh
docker compose port bridge 1143   # prints nothing (or an error): no host port
```

The first sync of a large mailbox can take hours. You can carry on in the
meantime, because IMAP clients see mail as it arrives.

## 4. Certificate

```sh
make cert
openssl x509 -in bridge-cert.pem -noout -subject -enddate
```

This writes `bridge-cert.pem` in the repo folder. Git ignores it. The live
check trusts this certificate and nothing else.

## 5. IMAP from a second container

```sh
make live-check
```

This starts a throwaway Python container on the private `mail` network and
prompts for the username and password from `info`. You should see:

```
ok: connected to bridge:1143: ...
ok: IMAP STARTTLS, certificate matches bridge-cert.pem
ok: IMAP login
ok: N folders
ok: INBOX opened read-only: N messages
live check passed (IMAP). Add SMTP=1 to also test sending.
```

INBOX is opened read-only, so nothing is marked as read.

## 6. SMTP (optional, sends one mail to yourself)

SMTP is off by default. Turn it on for this test only:

```sh
BRIDGE_FORWARD_SMTP=true docker compose up -d
make live-check SMTP=1
```

Look for **"Bridgekeep live check ..."** in your inbox. Then turn SMTP off
again:

```sh
docker compose up -d
```

## 7. Restarts keep the login

Each of these should come back `healthy` without another `make init`, and
`make live-check` should pass again afterwards:

```sh
docker compose restart bridge                    # restart
docker compose down && docker compose up -d      # recreate the container
```

Then quit Docker Desktop and start it again, or reboot Windows. `bridge` has
`restart: unless-stopped`, so it comes back by itself. Check it with
`docker compose ps` and `make live-check`.

Also check that the certificate didn't change:

```sh
cp bridge-cert.pem /tmp/cert-before.pem && make cert && cmp /tmp/cert-before.pem bridge-cert.pem && echo same
```

## 8. Auto-update dry run

Run these from the same shell where your login lives. With Docker Desktop
that's **Git Bash** in `C:\projects\bridgekeep-proton`, which Task Scheduler
also uses. With an engine inside WSL, use WSL, and skip the Task Scheduler
part: the daily schedule is tested on the Linux host instead
([operations.md](operations.md#updates)).

```sh
scripts/update-bridge.sh --check   # "up to date", exit 0 (10 means a newer Bridge is out)
scripts/auto-update.sh             # "up to date (Bridge 3.27.2); nothing to do"
```

Then run the full update path once without a new release:

```sh
scripts/auto-update.sh --force
```

This rebuilds the image and smoke-tests it, then stops with `UPDATE WAITING:
Bridge 3.27.2 is built and smoke-tested but not running yet`. Install it:

```sh
make deploy-update
```

That recreates `bridge` and waits for it to become healthy. It should end with
`updated: Bridge 3.27.2 is running and healthy`. If the new container doesn't
come up healthy, it rolls back to the previous image. Afterwards, `make live-check` in WSL should still pass with the
same login.

Finally, set up the daily task and run it once (see "Automatic updates" in
[operations.md](operations.md)):

```powershell
schtasks /Run /TN "Proton Bridge auto-update"
```

Then check `auto-update.log` in the repo folder.

## If something fails

| What you see | What to do |
|---|---|
| `make build` stops at the signature or sha256 check | Stop. Don't change the pins by hand. Open an issue with the output. |
| `login` rejects the 2FA code | Check the clock: `date` in WSL should match your phone. Run `wsl --shutdown` from PowerShell to resync it. |
| Stays `unhealthy` after login | `docker compose logs --tail 100 bridge`. If it says the session ended, run `make init` and `login` again. |
| `live-check`: cannot connect | `docker compose ps` must show healthy. The check only works on the `proton-bridge_mail` network. |
| `live-check`: certificate check failed | Run `make cert` again, then retry. |
| `live-check`: login refused | Use the username and password from `info`, not your Proton password. |
| `the input device is not a TTY` | Run it from WSL, not Git Bash. |
| `docker compose ... unknown flag: --rm` | No Compose plugin. Run `make preflight` and follow what it says. |

When everything passes, `preview` is ready to be promoted to `main`. If
anything fails, open an issue with what you saw.
